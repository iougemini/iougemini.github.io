## 目标

增加一条真正私密的投稿链路，同时保留现有公开 Issue 投稿：

- 愿意公开的投稿者：继续使用 GitHub Issue 模板；
- 不愿公开的投稿者：使用 `submit.ikms.eu.org` 的 Cloudflare Worker 表单；
- 私密投稿不会创建 GitHub Issue，不会把服务器地址写进公开页面或公开 `servers.json`；
- 管理员审核通过后，Worker 通过 GitHub `repository_dispatch` 触发现有加密候选池收录流程。

## 建议架构

### 1. Cloudflare Worker 私密投稿服务

新增 `workers/private-submit/worker.js`，Worker 提供：

- `GET /`：私密投稿表单，字段包括服务器地址、端口、备注、授权确认；
- `POST /api/submit`：校验域名/公网 IP 格式、端口范围、限流后写入 Cloudflare KV；
- `GET /admin`：管理员审核页面，不在 URL 中暴露密钥；
- `POST /api/admin/approve`：管理员批准某条投稿后，Worker 用自己的 GitHub Token 发送 `repository_dispatch`；
- `POST /api/admin/reject`：拒绝投稿并记录原因；
- 每个提交生成随机 ID，KV 保存状态、时间、备注、审核结果，不公开真实地址。

Worker 只做格式校验和私密保存，不在 Worker 中运行 vlmcs，避免引入 SSRF、运行环境和协议兼容问题。真正的收录仍由 GitHub Actions 完成。

需要新增 `workers/private-submit/README.md` 和 `wrangler.toml.example`，说明：

- 创建 KV namespace；
- 设置 Worker secrets：`ADMIN_KEY`、`GITHUB_TOKEN`；
- 设置变量：`GITHUB_REPOSITORY=iougemini/iougemini.github.io`；
- 配置自定义域名 `submit.ikms.eu.org`；
- Worker 不复用 Cloudflare DNS Token，投稿 Token 与 DNS Token 分离。

### 2. 私密收录 GitHub Actions

新增 `.github/workflows/kms-private-submit.yml`：

- 监听 `repository_dispatch` 类型 `kms-private-submit`；
- 校验 payload 中的地址和端口；
- 调用共享的 `kms-lib.mjs`，将投稿写入加密候选池；
- `trusted: true` 标记为管理员批准的投稿，避免国内线路被海外 CI 误判；
- 只提交脱敏的 `data/servers.json` 和加密的 `data/candidates.enc`；
- 不创建公开 issue，不在 Actions 日志打印真实地址。

新增 `scripts/add-private-submit.mjs`，复用现有 `loadData/saveData/normalizeHost`，处理去重、候选 key、加密和审计元数据。

### 3. 网站入口

在 `more.html` 的投稿提示区域增加两个明确入口：

- “公开投稿” → GitHub Issue 模板，并提示服务器地址会公开显示；
- “私密投稿” → `https://submit.ikms.eu.org`，提示仅管理员可见、需要管理员审核。

公开 Issue 模板继续保留授权确认；私密 Worker 表单使用单独的隐私同意文字，不复用“同意公开”的 Issue 模板。

### 4. 隐私清理

在实现 Worker 前先处理公开数据隐私：

- 检查当前 `data/servers.json` 是否残留候选 `host/port/ip/ips_ok/ip_lat`；
- 清理公开候选条目，只保留 `key/state/latency/stack/source` 等非地址字段；
- 确认 `data/candidates-private.json` 不被跟踪，`data/candidates.enc` 仍保留；
- 检查 git 历史是否又出现新的明文候选文件；如有，执行一次受控历史清理并强推，避免继续公开投稿地址；
- 保留现有 AES-256-GCM 加密和 `CANDIDATES_SECRET`，不把任何密钥写入 Worker 前端或仓库。

## 实施顺序

1. 读取并核对当前 `data/servers.json`、加密候选池、Issue 工作流和 `more.html`；
2. 清理/修复公开数据隐私；
3. 添加 `add-private-submit.mjs`、私密收录 workflow 和 Worker 源码/部署文档；
4. 增加 more.html 双入口；
5. 本地测试：地址校验、重复投稿、公开数据脱敏、私密 payload 收录、错误响应；
6. 检查 Worker/Actions 中没有把真实地址写入公开日志；
7. 提交并推送到 main；
8. 你在 Cloudflare 面板创建 KV、配置 Worker secrets 和自定义域名后，用一条测试投稿验证完整链路。

## 重要边界

Cloudflare Worker 的 KV 和管理员审核页面需要你的 Cloudflare 账号配置；我可以把源码、配置模板和 GitHub 工作流全部写好，但不会凭空生成或提交你的 `ADMIN_KEY`、GitHub Token、KV namespace ID。
