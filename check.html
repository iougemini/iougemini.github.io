Probe

KMS 地址在线检测

由 Cloudflare 边缘节点替你连到 1688 端口，做一次 TCP 连接与一次 MSRPC bind 握手，判断该地址是否跑着 KMS 端点，并给出延迟。

填写被测地址

1688 only
同一地址 2 分钟内重复提交会命中缓存；每 IP 每分钟最多 5 次。产品选择仅作标识，不参与判定。

检测没通过？先对照这几种情况

连接失败

1688 端口连不上。常见原因：KMS 服务没启动、防火墙或安全组没放开 1688、端口被改过、路由器没做端口映射。远程访问时防火墙要对所有来源 IP 放通，只放行少数 IP 会时通时不通。

非 KMS

端口是通的，但对面回的不是 KMS 的 RPC 接口。多半是地址写错了，或者那台机器的 1688 上跑的是别的服务。

超时

4 秒内没完成连接或握手：链路丢包、跨境线路拥塞，或目标被网络策略拦掉。可以稍后重试，或换一条备用线路再测。

域名解析失败

域名拼错、还没有解析记录，或只写了主机名。本站按公网 IPv4 的 A 记录解析，解析不到就不会继续连。

内网地址被拒

填的是 10/8、172.16/12、192.168/16、127/8 这类私网或保留地址，或者域名解析到了这些网段。本站只测公网 IPv4，不做内网扫描。

频率限制

同一地址 2 分钟内重复提交会命中缓存；同一 IP 每分钟最多 5 次、每天 100 次，全站每天 500 次。超了就等一会儿再试。

用自己的 telnet 主机 1688 或 nc -vz 主机 1688 能连通、这里却一直超时，通常是 Cloudflare 边缘到目标那一段跨境链路的问题，可以过一会儿再试，或从页脚「投稿反馈」告诉我们。

先看清楚：v4 / v5 / v6 是什么

v4 / v5 / v6 是 KMS 激活协议的版本号，与网络层的 IPv4 / IPv6 毫无关系——名字撞车纯属巧合，请不要因为看到 “v4” 就以为它和 IP 协议有关。

本页由服务端（Cloudflare Worker）代连，浏览器不直接连 1688。检测完成后你能看到：

  1. TCP 是否能连上 1688；
  2. 对端是否响应 MSRPC bind（KMS 的 RPC 接口）；
  3. 这次握手的往返延迟，以及域名解析到的 IP。

产品下拉里的 202 项来自公开接口 kms.pub/api/kms/getkmsapplist 的清单快照（2026-11-09 抓取，按 Windows / Windows Server / Office 分组）。选择产品目前只用于标识与回显，不代表已验证可激活——清单变大不等于检测能力变强，请不要据此认为本站能逐个验证这些产品。

当前版本不做激活报文（AES-CMAC / 产品密钥），所以无法回答「这个服务器能不能激活某个具体产品」，也无法真正验证 v4/v5/v6 哪一版生效——页面上这三项会显示“未验证”，不会用猜测冒充结论。

关于本检测：能做什么、不能做什么

  • 能做的只有可达性：1688 端口能否连上、对端是否响应 MSRPC bind、这次握手往返多久。这几项通过，只能说明该地址上像一个可用的 KMS 端点。
  • 做不到「能否激活」的判定：本检测不发送激活报文，所以无法确认服务器使用哪个协议版本（v4 / v5 / v6），也无法判断它能不能激活你手上的某个 Windows 或 Office 版本。结果只适合线路自查，不能当作激活成功的保证。
  • 结果只代表这一瞬间：KMS 服务重启、线路波动、防火墙策略调整都会改变结论；单次「可用」不等于长期稳定，反之亦然。
  • 定位说明：本站只做技术学习与线路排查，不搭建、不提供、不维护任何 KMS 主机或激活服务，页面里也不包含任何激活工具。是否使用、如何使用，请自行判断并承担后果，并支持正版授权。

边界与限制

  • 只开放 1688 端口，其它端口一律拒绝，避免被当成端口扫描器。
  • 只允许解析到公网 IPv4 的地址；私网、回环、链路本地、CGNAT 等保留段直接拒绝。
  • 接口只接受本站页面（https://ikms.eu.org）的跨域请求，其它来源会被服务端拒绝。
  • 单次探测 4 秒硬超时，失败不重试；结果缓存 120 秒削峰。
